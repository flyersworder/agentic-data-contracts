\section{Results}
\label{sec:results}

\subsection{Run B lost 29\% of its rows}
\label{sec:truncation}

We state this before the numbers, because every run~B figure is conditioned on
it.

Roughly 1{,}000 rows into run~B, the pinned provider endpoint began returning
HTTP 429. The harness had no retry for that status, so each throttled request
was written to the results file as a terminal error: 466 of 468 error rows are
rate limits. Error rate was 0.2\% over the first 1{,}000 rows, 31\% over the
next 200, and 100\% thereafter. The sweep then \emph{finished early}, because a
throttled request fails instantly, and exited cleanly.

The loss costs power, not validity, and the evidence for that is specific:

\begin{itemize}
\itemsep2pt
\item Errors are near-uniform across arms --- 113, 116, 118 and 121 of 401
      rows. No arm is preferentially damaged.
\item 114 of the 122 lost tasks lost \emph{all four} arms together, because
      the runner schedules a task's arms close in time. Independent per-arm
      failure would have left roughly 100 complete tasks; 279 survived.
      Missingness is a property of \emph{when} a task ran.
\item Complete-case figures and per-arm figures over each arm's own
      denominator agree to within one point.
\end{itemize}

We therefore report run~B on the 279 tasks scoreable in all four arms, with
intervals roughly 20\% wider than run~A's. One
residual caveat: the lost tasks are slightly enriched for hard tasks (87\%
hard against 83\% overall), so run~B's absolute accuracies are marginally optimistic. Every
arm is affected identically.

One lesson generalises beyond this paper. Pinning a single provider endpoint
with fallbacks disabled is correct for validity, since it holds quantization,
price and throughput fixed across arms, but it transfers responsibility for
transient failures to the harness, and here nothing looked wrong until the
results were read. Benchmark harnesses that pin endpoints need a
rate-of-progress check, not just a liveness check.

\subsection{What the third and fourth models changed}
\label{sec:reversals}

Runs~A and~B were run and analysed first, and three of this paper's claims were
written against them. Run~C overturned two and forced the withdrawal of a
third. We state the reversals here, together, so that the later sections can report
them at the number that overturned each: the scaffolding step is not zero
(Section~\ref{sec:ablation}); the contract's margin over a hand-written prompt
does not shrink with capability (Section~\ref{sec:interaction}); the contract
is not the cheapest arm (Section~\ref{sec:efficiency}). Each is reported below
at the number that overturned it. Everything else in this section held across
all four models.

Run~D, a fourth model from a fourth family, was run after those reversals were
written. It replicates the first two: the scaffolding step is $+15.1$ points at
$p{=}9{\times}10^{-9}$, and the margin over a hand-written prompt is $+44.6$,
the largest of the four. It also softens one claim the third model had
introduced --- that capability's gain lands almost entirely on the tasks the
contract's semantics answer outright (Section~\ref{sec:derivation}) --- and it
adds a case the first three did not contain: a model on which the pasted
manual is indistinguishable from a bare schema on hard tasks.

\armC{} wins every comparison on all four models
(Tables~\ref{tab:headline} and~\ref{tab:mcnemar}). On the two flash-tier
models it is also the cheapest arm, so there is no accuracy/cost trade-off to
report; on
run~C that coincidence ends, and on run~D it nearly returns
(Section~\ref{sec:efficiency}).

One check licenses those comparisons. \armM{}
reproduces the published leaderboard band on run~A: 22.9\% hard against a
20--26\% band for credible named entrants, on a model weaker than any of them.
On runs~B and~C the same arm reaches 42.9\% and 50.3\%, above the band, which
is a statement about those models rather than about the harness. Run~D
supplies the check on a second model family: 23.8\% for Sonnet~5, against the
leaderboard's 19.8\% for Claude~4 Sonnet under the same approach.

The easy split gives a second, negative check. \armC{} is not the best arm on
easy tasks in any of the four runs --- \armM{} leads on all four (73.9\%,
90.6\%, 94.2\%, 89.9\% against \armC{}'s 71.0\%, 81.1\%, 85.5\%, 75.4\%). The
contract does nothing for questions that need no domain knowledge, which is
what it should do, and an instrument that showed a contract effect there would
be measuring itself. On run~D the lead is an interaction rather than noise:
62 of 69 against exactly 52 for each of the other three arms. The transcripts
locate it. Of the 13 easy tasks \armM{} gets right and \armC{} gets wrong,
four are ones whose answer is a phrase printed verbatim in
\texttt{manual.md}, and the rest are prose answers the scorer cannot parse and
ordinary near-misses. None of it is fee semantics, and on the hard split the
same arm is last. Where else the effect is absent is reported in
Section~\ref{sec:threats}.

\paragraph{On one model the manual is indistinguishable from a bare schema on
hard tasks.} Run~D's \armM{} scores 79 of 332 hard tasks against \armS{}'s
76: paired McNemar on the hard split $p{=}0.72$, 17 discordant pairs one way
and 14 the other. The same 24{,}177-character prompt that lifts run~A by 9
points and run~B by 20 lifts Sonnet~5 by less than one; the contract carrying
the same knowledge lifts it by 45.5. Section~\ref{sec:clauses} shows the same
thing in the submitted SQL. This is the sharpest instance in any run of the
claim that delivery matters as much as possession, and it is also the one run
on which empty governed tools (38.0\%) beat the whole manual (23.8\%), hard
split $p{=}6{\times}10^{-8}$ (15/62). One alternative is not excluded: that
prompt puts 191k input tokens per task in front of Sonnet~5 against \armS{}'s
91k, and a context-load effect would produce the same null without any
delivery mechanism. The clause analysis finds the manual's rules absent from
the submitted SQL rather than misapplied, which is what either explanation
predicts, so the two are not separated here.

not zero}
\label{sec:ablation}

On hard tasks the gain splits into a scaffolding step and a content step. The
ladder runs \armS{} to \armH{} to \armC{} --- 13.9 to 19.3 to 55.1 on run~A,
22.6 to 22.6 to 56.6 on run~B, 37.0 to 51.2 to 77.4 on run~C, and 22.9 to
38.0 to 68.4 on run~D (Figure~\ref{fig:ablation}; the same rows in Table~\ref{tab:headline}, costs
and work in Table~\ref{tab:efficiency}).

\textbf{The content step is the larger of the two on every model. The
scaffolding step is model-dependent: absent on one model, marginal on one,
substantial on two.}

On runs~A and~B alone the scaffolding step did not survive a significance
test, and a pooled $p{=}0.29$ with disagreeing signs looked like evidence of
absence. It was evidence of a capability range too narrow to show the effect. Three of
four models favour the scaffolding and one is flat; none favours the bare
schema, and the two that favour it most are from different model families.\footnote{On run~A
the hard slice alone is already $p{=}0.015$ (16/34); the 0.058 above is the
all-401 test, diluted by the easy tasks.}

What the fourth arm was built to test survives intact. The deflationary
reading --- that the contract helps through a narrowed table surface, an
imposed procedure, or simply making the agent slow down --- predicts \armH{}
captures most of the gain. It does not, on any model: the content step is
$1.8{\times}$ the scaffolding step on run~C, $2.0{\times}$ on run~D,
$6.6{\times}$ on run~A, and the whole of the effect on run~B, where the
scaffolding step is zero. \textbf{Scaffolding is a real but secondary effect that the content
dominates everywhere.}

\paragraph{Empty tools are not free.} In run~A, \armH{} burns the most
reasoning of any arm (525k tokens against \armC{}'s 154k) and costs
\$0.0080 per correct answer against \armC{}'s \$0.0029. In run~B it makes the
most tool calls of any arm (6{,}375 against 4{,}155) for the fewest correct
answers. In run~C it is the most expensive arm outright (\$22.09) and the only
arm of the four to exhaust its output budget. In run~D it is again the most
expensive arm (\$46.08), makes the most tool calls (6{,}494), burns the most
reasoning (1{,}411k tokens, $1.7{\times}$ \armC{}'s) and forces 27 answers. The
transcripts show why: the agent calls \texttt{lookup\_domain}, is told nothing
is available, and searches harder. On run~C it makes that call on 401 of 401
tasks, 804 times in total; on run~D, 392 times, plus 1{,}620 calls to
\texttt{lookup\_metric} with every metric emptied. The models that gain most
from the scaffolding are also the ones that exercise the lookup tools
hardest.

\armC{} is not thinking harder; it has less to search for. That holds on all
four models: it uses the fewest turns everywhere and the least reasoning
everywhere --- by a factor of two to three on runs~A--C, by 12\% on run~D ---
and it is the only arm that never exhausted its output budget on any run. Table~\ref{tab:efficiency} sits beside the accuracy table because
reporting accuracy without cost yields needlessly expensive agents and
mistaken conclusions about where accuracy comes
from~\cite{agents-that-matter}.

\textbf{The cost claim does not survive run~C, and we withdraw it as a general
statement.} On the two flash-tier models \armC{} is the cheapest arm outright. On
\texttt{gpt-5.6-sol} it costs \$21.32 against \armM{}'s \$14.42: the contract's
own text is a real input-token bill, and a model whose output tokens are
expensive relative to its input tokens amortises that bill differently. Per
correct answer the ordering nearly closes (\$0.067 against \$0.062) but \armM{}
still edges it. Run~D sits between: \armS{} is cheaper outright by \$1.17 on
a \$37.97 bill, and per correct answer \armC{} costs \$0.136 against \$0.259
for the next arm. On three of four models the contract arm is the cheapest
way to buy a correct answer; on all four it is the least work. What
generalises is the work claim, not the price claim.

\subsection{The contract compiles, and the residual gap is derivation}
\label{sec:derivation}

Every result so far compares arms to each other. None of them says how much of
the contract's own content an agent recovers, because nothing establishes what
recovering all of it would look like. We can establish that, because the
contract is executable in a sense we did not design for.

The frozen artifact carries a \texttt{sql\_expression} field on each declared
metric. We transcribed those fields into two DuckDB views: the fee-rule match
predicate, the natural-month reconstruction, the monthly volume and fraud-level
aggregates, the fee formula, and the instruction to sum over all matched
(transaction, rule) pairs. The result is a pre-computed fee layer of the kind a
context-layer product ships. Nothing in it is authored independently of the
contract. The only work the transcription adds is \emph{composition}:
correlating the two placeholders in the month-scoped predicate to a
per-merchant aggregate.

\textbf{The compiled contract reproduces the benchmark's gold answers exactly
on every task it covers: 176 of 176, graded by the official scorer.} This is a
statement about the artifact, not about an agent, and it has two uses.

First, it forecloses an objection we cannot otherwise answer: that \armC{} wins
because the contract is subtly wrong in a benchmark-favouring way. It is not
wrong; it compiles to gold.

Second, it converts accuracy into \emph{efficiency against a proven ceiling}.
Classifying all 401 tasks by question shape alone, never by gold and never by
any arm's output, gives 176 tasks the compiled contract answers outright
(all hard), 148 that need those semantics \emph{plus} a counterfactual or an
optimisation it does not encode, and 77 with no fee semantics at all. A
pre-computed macro layer \emph{of this kind} therefore reaches 53\% of the hard
set on this benchmark. We do not offer that as a bound on pre-computation in
general --- Section~\ref{sec:related} reports a hierarchical semantic layer
reaching 100\% here --- only on a layer compiled from a domain contract's
declared expressions. On the 176 where the information is provably
sufficient, whatever an agent fails to get is a failure to derive
(Table~\ref{tab:buckets}).

Two qualifications on the 176 itself. The 97 tasks in the seven payments
families exercise the full \texttt{payments}-to-\texttt{fees} join that the
two views encode; the other 79 resolve off \texttt{fees} and
\texttt{merchant\_category\_codes} alone, using the same wildcard predicates
transcribed from the same contract fields but not the join. And 59 of those 79
--- the three fee-average families --- are exactly the tasks whose golds
Section~\ref{sec:golds} verified against the database using the same matching
rule the contract declares. On that subset the compiled contract and the gold
check share a premise, so it is a consistency check, not an independent one.
The other 117 are graded against consensus golds we did not recompute, and they
are what carries the claim.

Three readings follow.

\textbf{The contract's advantage concentrates where its semantics apply
directly.} Over \armS{} it is $+58.0$, $+54.2$, $+67.1$ and $+63.1$ points on
\emph{macro} against $+20.9$, $+11.8$, $+22.3$ and $+14.9$ on \emph{derived}. This is
the same domain-specificity as the fee/non-fee split
(Section~\ref{sec:threats}), measured on a cleaner boundary.

\textbf{The two buckets do not move together.} In order of bare-schema
capability \armC{} scores 60.8\%, 62.7\%, 73.9\% and \textbf{94.9\%} on
\emph{macro} against 45.9\%, 46.5\%, \textbf{60.1\%} and 56.1\% on
\emph{derived}. Ordered by bare-schema score the \emph{macro} series is
monotone, though runs~B and~D are 0.3 points apart on that axis and 11 apart
on \emph{macro}, so the ordering between them is not one the axis can
establish; the \emph{derived} series is not monotone under any ordering ---
Sonnet~5 is the best of the four models on it while trailing
\texttt{gpt-5.6-sol} by 21 points on \emph{macro}. An earlier version of this
paper, written against three models, said that nearly all of
\texttt{gpt-5.6-sol}'s gain lands on the tasks the contract's own semantics
answer. That was a description of one model: Sonnet~5's gain over
\texttt{deepseek-v4-flash} is $+11.2$ on \emph{macro} and $+13.6$ on
\emph{derived}. What survives four models is narrower --- the \emph{macro} gap
is smaller on both frontier-class models, and the \emph{derived} bucket does
not track it.

Read against the compiled ceiling, the \emph{macro} series is a shortfall of
39.2, 37.3, 26.1 and 5.1 points below an accuracy we have proven reachable --- the
\emph{derivation gap}, the price of making an agent derive a query the
contract could have pre-computed. That framing is worth stating carefully,
because against a ceiling of 100\% the gap is arithmetically the arm's error
rate, and ``errors fall as models improve'' is not a finding. The finding is
the contrast with \emph{derived}: between the flash models and the strongest
one, the same capability increment closes 87\% of the macro-bucket gap and
19\% of the derived-bucket one (the latter measured against 100\%, which is
not a proven ceiling on that bucket), and the fourth model's \emph{macro}
score falls between the flash models and run~C while its \emph{derived} score
exceeds all three. On two models the
macro gap looked like a fixed ${\approx}38$-point tax, model-invariant to
within two points. It is not a tax. We recorded this prediction in the public
artifact repository before run~C executed, stating that the capability reading
predicted ``well above 62.7\%, moving toward 100\%'' and the harness reading
predicted ``near 61--63\% like the other two''. The observed value is 94.9\%.
Run~D, executed after this section was written, was not covered by that
prediction; it lands at 73.9\%, above the harness reading's 61--63\% and below
run~C. The direction of the collapse replicated on a fourth model family; its
size did not.

This bears directly on the economics in Section~\ref{sec:intro}. The derivation
gap is exactly what separates a declarative contract, which requires the agent
to derive the query, from pre-computed macros, which do not. A gap fixed at 38
points would be a standing structural cost of the declarative approach. A gap
that falls to 5 points on the strongest model is a \emph{transient} cost, one the
trend in model capability is already paying down, while the per-metric
authoring cost of a macro layer is paid down by nothing.

What survives the strongest model, then, is not difficulty in knowing the
domain. It is the counterfactual and optimisation reasoning built on top of
it, on which the four models have no clean ordering.

\subsection{The margin over a prompt is not monotone in capability}
\label{sec:interaction}

Ordered by what each model achieves from a bare schema
(Figure~\ref{fig:interaction} and Table~\ref{tab:interaction}), the contract's
margin over \armM{} runs $+32.2$, $+13.7$, $+44.6$ and $+27.1$. With two models this
looked like a clean interaction: \armM{} improved by 20.0 points while
\armC{} moved 1.5, and the lines converged. Two readings were available.
Structured context might substitute for capability, so that a stronger model
extracts the same semantics from prose unaided and the margin keeps shrinking;
or \armC{} might have been pinned near a benchmark ceiling at ${\approx}56\%$
while \armM{} rose to meet it. Run~C reached \textbf{77.4\%}, so there is no
ceiling at 56\%, and its $+27.1$ refutes the shrinking margin; run~D's
$+44.6$ is the largest of the four, on a model whose bare-schema score ties
run~B's. Whatever governs the size of the contract's advantage over a
hand-written prompt, it is not a monotone function of base capability, and
four points cannot support a third story. Run~D adds one thing to that: the
bare-schema score is a poor proxy for what a model does with structure.
Sonnet~5 and \texttt{deepseek-v4-flash} are 0.3 points apart on it and 11.8
points apart with the contract.
